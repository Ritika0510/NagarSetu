Citation enforcement points, in order of the pipeline:

[CITE-1] Prompt level — backend/llm/prompts.py, SYSTEM_PROMPT rules 2 and 7. Instructs the model to cite and forbids inventing procedure_id. [CITE-2] Verification level — backend/rag/verify.py, verify(). Deterministic post-generation check; steps citing unknown chunk_ids render with verified: false and an amber warning in the UI. [CITE-3] Guardrail level — backend/rag/verify.py, _modal_procedure(). Overrides a fabricated procedure_id with the grounded value; every override emits a log line beginning "PROCEDURE_ID_OVERRIDE:".

Walkthrough: one query, end to end
User types "I want to open a small shop in Chandigarh" inChatPanel (frontend/components/ChatPanel.tsx, handleSubmit).

ChatPanel calls sendChat (frontend/lib/api.ts). If demo modeis active (?demo=true or NEXT_PUBLIC_DEMO_MODE), the bundleddemo cache in frontend/lib/demo/*.json answers without anynetwork call. Otherwise, fetch with a 15-second AbortControllertimeout and one silent retry (Task 4 hardening).
The request reaches chat (backend/routers/chat.py). Thefunction _detect_procedure matches "shop" and returns"chandigarh_trade_license".
retrieve (backend/rag/retrieve.py) embeds the query withall-MiniLM-L6-v2, queries ChromaDB and the BM25 index, fusesboth ranked lists with rrf_merge (k=60), filters tochandigarh_trade_license chunks, returns top 8.
evaluate_scope (backend/rag/scope.py) checks the query againstOUT_OF_SCOPE_PATTERNS and the retrieval result. In-scopequeries proceed; out-of-scope queries return a refusal dictwith three working suggestions and generation never runs.
build_system_prompt (backend/llm/prompts.py) injects theschema, the dynamic valid procedure_id list derived from theretrieved chunks, and the citation rules. build_user_promptformats the chunks with their Procedure ID and chunk_id lines.
generate (backend/llm/client.py) calls Groq(JSON response_format), falls back to Gemini, then to theserver-side demo cache. Latency is logged per call.
verify (backend/rag/verify.py) checks every step'ssource_chunk_ids against the retrieved chunk set, marks eachstep verified or not, forces low confidence past 30%unverified, and overrides procedure_id/procedure_name withthe modal retrieved chunk's values (_modal_procedure).
Checklist.model_validate (backend/models/schemas.py) enforcesthe strict schema. Malformed output is rejected, never passedto the UI as free text.
The frontend renders the checklist (ChecklistCard, StepItem,SourcePopover). Step completion POSTs to /api/progress and isstored in SQLite (backend/db/progress.py), keyed by anonymoussession_id; progress survives page refresh.
